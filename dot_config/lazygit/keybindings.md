# lazygit 操作メモ

このファイルは、よく使う操作と低頻度機能の使い方を用途別にまとめたものです。
lazygit 上で `Ctrl-g` を押すと、読み取り専用で開きます。

現在のパネルで利用できる操作を確認するには `?` を押してください。
`?` の一覧はパネルごとの完全な一覧です。

## 基本操作

| キー      | 操作                               |
| --------- | ---------------------------------- |
| `j` / `k` | 下 / 上へ移動                      |
| `h` / `l` | 前 / 次のパネルへ移動              |
| `Tab`     | パネルを切り替え                   |
| `1` - `5` | パネルへ直接移動                   |
| `/`       | 現在のパネルを検索・絞り込み       |
| `?`       | 現在のパネルのキーバインド一覧     |
| `@`       | コマンドログの操作メニュー         |
| `:`       | シェルコマンドを実行               |
| `R`       | リポジトリの状態を更新             |
| `Y`       | 選択中の値をクリップボードへコピー |
| `q`       | 終了                               |

## ファイルとステージング

| キー    | 操作                                        |
| ------- | ------------------------------------------- |
| `Space` | ファイル・ハンクをステージ / アンステージ   |
| `v`     | 行の範囲選択を開始                          |
| `a`     | 全ファイル、または現在のハンクを選択        |
| `Enter` | ステージング画面へ移動 / ディレクトリを展開 |
| `c`     | ステージ済みの変更をコミット                |
| `w`     | pre-commit hook を実行せずコミット          |
| `C`     | Git エディタでコミット                      |
| `d`     | 破棄メニュー                                |
| `s`     | 変更を stash                                |
| `f`     | fetch                                       |
| `r`     | ファイルを更新                              |

通常の未コミット変更の一部だけをコミットしたい場合は、Files パネルで
`Enter` からステージング画面へ入り、`Space` で必要な行だけをステージします。

## ブランチと worktree

| キー    | 操作                        |
| ------- | --------------------------- |
| `n`     | ブランチを作成              |
| `c`     | 名前を指定して checkout     |
| `Space` | 選択中のブランチへ checkout |
| `w`     | worktree を作成             |
| `r`     | rebase                      |
| `M`     | merge                       |
| `d`     | 削除                        |
| `R`     | 名前を変更                  |

`w` で作成する worktree は、リポジトリ直下の次の場所に作成します。

```text
<repository>/.worktrees/<branch-name>
```

ブランチごとに作業ディレクトリを分けられるため、ブランチ切り替えのたびに
stash や WIP commit を作る必要がなくなります。

## コミットと履歴

| キー      | 操作                                          |
| --------- | --------------------------------------------- |
| `i`       | interactive rebase を開始                     |
| `s`       | squash: コミットを下のコミットへ統合          |
| `f`       | fixup: メッセージを破棄して下のコミットへ統合 |
| `d`       | コミットを削除                                |
| `e`       | コミットを編集                                |
| `A`       | 選択したコミットを amend                      |
| `C` / `V` | cherry-pick 用にコピー / 貼り付け             |
| `z` / `Z` | 直前の Git 操作を undo / redo                 |
| `b`       | bisect メニュー                               |

### リモートとの同期

| キー | 操作 |
| ---- | ---- |
| `P`  | push |
| `p`  | pull |

## パッチ

`Ctrl-p` でパッチ操作メニューを開きます。

### 何に使うか

パッチ機能は、過去のコミットに含まれる変更のうち、特定のファイルや行だけを
選んで編集する機能です。例えば、過去のコミットに不要なコメントが混ざっていた
場合に、そのコメントだけをコミットから取り除けます。

現在の未コミット変更を部分的にステージする操作とは別物です。

### 操作手順

1. Commits パネルで対象のコミットを選択し、`Enter` を押す
2. 対象ファイルを選択し、`Enter` を押す
3. 対象の行で `Space` を押してパッチに追加する
4. `Ctrl-p` でパッチ操作メニューを開く
5. パッチの削除、別コミット化、index への逆適用などを選択する

過去のコミットを書き換える操作なので、共有済みのコミットに対して実行する
場合は注意してください。迷った場合は、先にブランチを作るかバックアップを
作成してから実行します。

## bisect

### 何に使うか

bisect は、ある不具合を導入したコミットを、コミット履歴の二分探索で特定する
機能です。正常だったコミットと不具合が発生したコミットが分かっている場合に
有効です。

### 操作手順

1. 作業ツリーを clean にする
2. Commits パネルで `b` を押して bisect メニューを開く
3. 不具合があるコミットを `bad`、正常なコミットを `good` として指定する
4. lazygit が checkout したコミットでテストを実行する
5. 不具合があれば `bad`、なければ `good` として `b` から記録する
6. 原因のコミットが特定されるまで繰り返す

コミット数が多くても、必要なテスト回数はおおむね `log2(コミット数)` 回です。
途中で中止・リセットしたい場合も、`b` の bisect メニューから操作します。

### テストの実行方法

テストは、対象コミットを checkout した状態で通常どおり実行します。

- lazygit 内で `:` を押してテストコマンドを実行する
- 別のターミナルでテストコマンドを実行する
- テスト結果を確認し、lazygit の `b` メニューから `good` / `bad` を選ぶ

例えば、特定の不具合を再現するテストが `./test-regression.sh` の場合は、各段階で
次のように実行します。

```sh
./test-regression.sh
```

不具合が再現したら `bad`、再現しなければ `good` です。テストは同じ条件で
判定できるようにし、失敗が不具合ではなく環境依存の場合は `skip` を使います。

### 自動実行

判定を終了ステータスで表現できる場合は、lazygit の外で `git bisect run` を使えます。

```sh
git bisect run ./test-regression.sh
```

終了ステータスは、`0` が good、`1` から `127` が bad、`125` が skip です。
テスト終了後は `git bisect reset` で通常のブランチへ戻します。

## rebase

rebase には、コミット履歴を整理する操作と、現在のブランチを別のブランチの
先端へ載せ替える操作があります。どちらも履歴を書き換えるため、作業ツリーを
clean にしてから実行します。

### コミット履歴を整理する

1. Commits パネルで `i` を押して interactive rebase を開始する
2. 対象コミットを選択する
3. 目的に応じて操作する
   - `s`: squash。下のコミットと統合し、メッセージを編集する
   - `f`: fixup。下のコミットと統合し、対象のメッセージを破棄する
   - `d`: drop。コミットを削除する
   - `e`: edit。コミットの内容を編集する
   - `Ctrl-j` / `Ctrl-k`: コミットを下 / 上へ移動する
4. `m` で rebase メニューを開き、`continue` を実行する

競合が発生した場合は、Files パネルで競合を解決してステージし、`m` の
`continue` を実行します。やり直したい場合は `abort`、現在のコミットを飛ばす
場合は `skip` を選びます。

### 別ブランチへ載せ替える

現在のブランチを、別のブランチの最新状態を基準に載せ替える場合は、Branches
パネルで対象ブランチを選択して `r` を押します。現在 checkout 中のブランチが、
選択したブランチの上に rebase されます。

履歴の一部だけを載せ替えたい場合は、Commits パネルで基準にしたいコミットを
選択して `B` を押してから、Branches パネルで対象ブランチに `r` を実行します。
これにより、マークした基準コミットより後のコミットだけを載せ替えられます。

### 注意点

- push 済みの共有ブランチでは、他の人の履歴を壊す可能性がある
- rebase 後の push では通常の push が拒否されるため、必要なら force push が必要
- rebase 中は `m` から `continue` / `abort` / `skip` を選ぶ
- 迷った場合は `z` で直前の Git 操作を undo できるが、事前のバックアップも推奨
